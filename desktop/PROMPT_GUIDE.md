# 만들기 · 프롬프트 결과 수집

선택한 원본마다 공통 프롬프트 3개를 등록 순서대로 실행. 각 프롬프트마다 원본을 다시 열어 생성 후 저장. 직전 생성 결과에 다음 프롬프트를 이어서 적용하지 않음.

## 실행

최신 저장소 ZIP 압축 해제 후 VS Code에서 `desktop` 폴더 열기. 기존 사용자는 `app(prompt).py`, `app.py`, `automation.py` 모두 최신 파일로 교체 필요.

```powershell
python -m pip install -r requirements.txt
python "app(prompt).py"
```

기존 패키지 설치 완료 시 두 번째 명령만 실행. 괄호가 포함된 파일명은 따옴표 사용.

- 스타일 실행: `python app.py`
- 만들기 실행: `python "app(prompt).py"`
- 공통 UI: `app.py`. 공통 폰 조작: `automation.py`.
- `app(prompt).py`만 단독 복사하여 실행 불가. 같은 폴더의 공통 파일 필요.
- 기존 EXE 빌드는 스타일 실행용. 만들기는 위 Python 명령으로 실행.
- Windows에서 두 버전 동시 실행 제한. 기존 창 종료 후 다른 버전 실행.

## 처음 한 번 · 버튼 등록

`02 버튼 · 프롬프트` 메뉴의 기기 찾기 → 연결 기기 선택.
폰에서 아래 화면을 직접 열고, 매 단계 PC의 **현재 폰 화면의 버튼 읽기** 실행 후 해당 항목 선택 및 지정.

| 폰 화면 | 선택할 항목 | PC 등록 버튼 |
|---|---|---|
| 갤러리 원본 사진 | 포토 어시스트 | 포토 어시스트 지정 |
| 포토 어시스트 | 만들기 | 만들기 탭 지정 |
| 만들기, 입력 전 | 바꾸고 싶은 내용을 적어 보세요 등의 입력창 | 입력칸 지정 |
| 입력창 탭 후 문구 직접 입력 | 활성화된 생성 버튼 | 생성 버튼 지정 |
| 직접 생성 완료 | 다른 파일로 저장 | 다른 파일로 저장 지정 |

입력창은 매번 비어 있는 초기 화면에서 찾을 수 있는 항목으로 등록. 임시로 입력한 문구 자체를 입력칸 식별값으로 등록하지 않음. 원본 덮어쓰기 버튼 지정 금지.

## 프롬프트 3개 등록

오른쪽 프롬프트 구성 카드에서 문구 입력 → 프롬프트 추가, 총 3회 반복.
예: `모자를 씌워줘`, `목도리를 둘러줘`, `배경을 해변으로 바꿔줘`.

- 같은 3개 문구를 선택한 모든 사진에 적용.
- 공백만 있는 문구 및 중복 문구 등록 제한.
- 변경: 기존 문구 선택 → 삭제 → 새 문구 추가. 실행 순서는 목록 순서.
- 전체 실행은 정확히 3개 필요. 한 장 시험은 첫 문구 하나로 가능.
- 버튼과 문구는 등록 시 자동 저장.

## 실행 순서

1. 결과 수집 → 사진 목록 불러오기 → 폴더 및 원본만 선택.
2. 첫 사진 · 첫 프롬프트 시험 선택. 실제 생성·저장 수행.
3. 폰에서 입력 문구·생성 결과·원본 유지·저장 위치 확인.
4. 새 작업 → 원본 선택 → 전체 수집 시작.

사진 A → 문구 1 생성·저장 → A 원본 다시 열기 → 문구 2 생성·저장 → A 원본 다시 열기 → 문구 3 생성·저장 → 사진 B로 반복.

생성 결과 중 처음 표시된 한 장 저장. 결과 후보들을 스와이프하여 전부 저장하는 기능 제외.
시험 결과는 전체 실행에 다시 포함하면 중복 생성 가능.

## 기록과 제한

만들기 설정·진행 기록: `%LOCALAPPDATA%\PhotoAssistCollector\prompt`.
스타일 설정·진행 기록과 별도 보관. 프로필 내부 `styles`는 공통 실행 목록이며, 만들기에서는 `name`과 `prompt`를 저장.

입력창 탭 후 활성 입력칸의 내용을 교체하고 화면의 실제 문구 일치 여부 확인. 입력칸을 읽을 수 없거나 입력 문구가 다르면 생성 전 중단. 추가 키보드 설치를 자동으로 시도하지 않음.
생성 후 저장 버튼 최대 대기 180초, 저장 파일 확인 최대 45초. 원본과 같은 폴더의 새 파일 한 장 확인. 저장 폴더가 다르면 자동 이동 없이 중단.
