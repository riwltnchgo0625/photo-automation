# Photo Assist 결과 수집기 사용설명서

이 문서는 현재 `desktop/app.py`와 `desktop/automation.py`의 동작을 기준으로 작성.

## 1. 무엇을 하는 프로그램인가요?

폰에 이미 저장된 원본 사진을 대상으로 Photo Assist의 스타일 생성과 저장을 반복함. 사진을 PC에 업로드할 필요가 없음.

1. PC에서 폰의 사진 목록을 불러오기.
2. 대상 폴더와 원본 사진을 선택.
3. 원본 한 장을 열고 첫 번째 등록 스타일을 적용해 새 파일로 저장.
4. 같은 원본을 다시 열고 다음 스타일을 적용.
5. 등록한 스타일이 끝나면 다음 원본으로 이동.
6. 결과 사진은 폰에서 확인하고 사람이 품질을 평가함.

프로그램은 갤러리의 앨범을 화면에서 직접 탐색하지 않고, 사진 ID로 원본을 열기. 폴더 전체 자동 선택 기능은 없으므로 처리할 원본들을 선택해야 함. 스타일도 자동 수집하지 않고 등록된 항목만 실행.

**S26+ 한 장·3d 툰 실행 성공 보고. 여러 장·스타일 연속 실행 및 화면 누적 수정 효과는 실기기 확인 필요. PC 테스트 통과와 실제 폰 동작 검증은 별개.**

## 2. 준비할 것

| 항목 | 준비 내용 |
|---|---|
| PC | Windows x64. 빌드·테스트 기준 Python은 3.12임. |
| 폰 | Photo Assist를 직접 실행할 수 있는 갤럭시. 초기 로그인·약관·필요한 다운로드는 폰에서 완료함. |
| 케이블 | 데이터 전송을 지원하는 USB 케이블. PC 포트가 지원하면 C to C도 사용. |
| 연결 | 폰 잠금 해제, USB 디버깅 및 본인 PC 연결 허용 |
| 드라이버 | 기기가 인식되지 않으면 삼성 USB 드라이버 설치 여부를 확인. |
| 인터넷 | Photo Assist가 생성을 수행할 수 있는 폰의 네트워크 환경 |
| 테스트 사진 | 처음에는 별도 앨범에 복사본 1~2장을 준비함. |

Node.js, Docker, Appium 서버는 사용하지 않음. Python 가상환경은 선택 사항임. 내부 ADB 통신과 폰의 자동화 보조 프로그램은 사용하며, 사용자가 별도 서버 URL을 입력하지 않음.

## 3. VS Code에서 소스로 실행하기

### 3-1. 프로젝트 열기

GitHub에서 ZIP을 받았다면 먼저 압축을 해제. VS Code의 **파일 → 폴더 열기**로 `photo-automation-main`을 열기. 왼쪽에 `desktop`이 보여야 함.

`desktop` 안의 주요 파일:

| 파일 | 용도 |
|---|---|
| app.py | 창과 버튼, 설정, 사진 선택 |
| automation.py | 폰 연결, UI 조작, 생성 반복, 저장 확인 |
| requirements.txt | 실행에 필요한 Python 패키지 목록 |
| requirements-build.txt / build.ps1 | EXE를 만드는 개발용 파일 |
| tests | 동작 로직 테스트 |

### 3-2. 터미널 위치 맞추기

왼쪽 `desktop` 폴더를 우클릭해 **통합 터미널에서 열기**를 선택.

프로젝트 최상위에서 터미널을 열었다면:

```powershell
cd desktop
dir
```

목록에 `app.py`, `automation.py`, `requirements.txt`가 보여야 함. 이미 경로 끝이 `\desktop>`이면 다시 `cd desktop`을 입력하지 않음.

### 3-3. 설치와 실행

명령을 한 줄씩 실행.

```powershell
python --version
python -m pip install -r requirements.txt
python app.py
```

패키지 설치는 처음 또는 requirements 변경 시 필요. 설치 오류가 있으면 실행으로 넘어가지 말고 오류 내용을 확인. 다른 Python 버전의 호환성은 별도로 확인해야 함.

다음번에는 같은 폴더에서 `python app.py`만 실행하면 됨. 프로그램 창이 떠 있는 동안 터미널이 다음 명령을 기다리지 않는 것은 정상임.

코드를 수정한 뒤에는 Ctrl+S로 저장하고, 실행 중인 프로그램을 정상 종료한 다음 다시 실행. 소스 수정은 기존 EXE에 자동 반영되지 않음.

## 4. EXE로 실행하는 경우

1. GitHub **Actions → Build Windows EXE → 성공한 실행 → Artifacts**에서 배포 파일을 다운로드.
2. 압축을 해제. 안에 ZIP이 있으면 한 번 더 해제.
3. `PhotoAssistCollector.exe`를 실행.
4. EXE 옆의 `_internal` 폴더를 함께 유지.

EXE 배포본은 Python 실행 환경과 필요한 패키지·ADB를 묶음. EXE만 따로 복사하면 실행되지 않을 수 있음. 미서명 개발용 프로그램이며 회사 정책에 따른 실행 제한을 자동으로 해제하지 않음.

## 5. 상단: 기기 연결

1. 폰을 USB로 연결하고 잠금을 해제.
2. 폰의 개발자 옵션에서 USB 디버깅이 켜져 있는지 확인.
3. 폰에 연결 허용 창이 나오면 본인 PC인지 확인하고 허용함.
4. 프로그램의 **기기 찾기**를 클릭.
5. `기기 선택 완료.`가 표시되는지 확인. 여러 대라면 상단 선택 상자에서 대상 기기를 선택.

파일 탐색기에 폰 저장공간이 보이는 것만으로 ADB 연결까지 확인된 것은 아님. 기기 찾기는 연결 확인 단계이며 사진을 편집하지 않음.

다른 기기를 선택하거나 기기 찾기를 다시 실행하면 불러온 사진 선택은 초기화. 버튼 설정은 자동으로 기기별 분리되지 않으므로 다른 폰에서는 다시 확인해야 함.

## 6. 처음 한 번: 버튼 설정

### 공통 원리

**폰에서 화면을 직접 열기 → PC에서 현재 폰 화면의 버튼 읽기 → 목록에서 항목 선택 → 역할 지정** 순서임.

- 읽기: 현재 화면 요소의 이름·설명·ID를 조회. 사진을 PC에 복사하지 않음.
- 지정: 선택한 요소를 어떤 역할로 쓸지 저장. 폰의 해당 버튼을 클릭하는 기능이 아님.
- 화면을 바꿀 때마다 다시 읽어야 함. 목록은 자동으로 갱신되지 않음.
- 최초 읽기 때 폰에 자동화용 보조 프로그램이 배치·실행될 수 있음.
- 목록에는 버튼 외의 텍스트도 나올 수 있음. 이름만 비슷한 항목을 임의로 지정하지 않음.

### 6-1. 포토어시스트 등록

1. 폰 갤러리에서 테스트용 원본 사진을 열기.
2. PC의 **버튼 · 스타일** 메뉴을 열기.
3. **현재 폰 화면의 버튼 읽기**를 클릭.
4. 목록에서 포토어시스트에 해당하는 항목을 선택.
5. **포토 어시스트 지정**을 클릭.

### 6-2. 스타일 탭 등록

1. 폰에서 직접 포토어시스트로 들어갑니다.
2. 스타일로 들어가는 버튼이 보이는 상태에서 PC의 **현재 폰 화면의 버튼 읽기**를 클릭.
3. 해당 항목을 선택하고 **스타일 탭 지정**을 클릭.

### 6-3. 목록 펼치기: 필요한 경우만

스타일 탭 진입 후 별도의 더보기 버튼을 눌러야 스타일 목록이 나타나는 경우, 그 버튼이 보일 때 읽고 **목록 펼치기 지정**을 클릭.

필요 없다면 지정하지 않음. 잘못 지정했다면 **목록 펼치기 설정 해제**를 클릭. 현재는 모든 스타일에 공통으로 적용하는 한 단계만 지원.

### 6-4. 스타일 등록

1. 폰에서 스타일 목록을 직접 열기.
2. PC에서 화면의 버튼을 읽기.
3. 처리할 스타일에 해당하는 항목을 선택.
4. **스타일 이름**에 실제 이름을 입력. 이 이름은 진행 기록에도 사용됨.
5. 바로 보이는 스타일이면 **처음 목록에서 왼쪽 스와이프 횟수**를 `0`으로 둡니다.
6. **선택한 버튼을 스타일로 추가**를 클릭.
7. 아래 등록 목록에 이름이 생겼는지 확인.

가로 목록을 넘겨야 보이는 스타일은 초기 목록에서 왼쪽으로 넘기는 횟수(0~20)를 입력. 직전 등록 스타일부터의 횟수가 아님. 손으로 넘긴 거리와 프로그램의 고정 스와이프 거리는 다를 수 있으므로 실제 실행으로 맞춰야 함. 목록이 매번 처음 위치로 돌아오는지도 확인해야 함.

처음에는 바로 보이는 스타일 하나만 등록. 나머지는 첫 시험 성공 후 추가함. 스타일 실행 순서는 등록 순서임. 순서를 바꾸는 전용 버튼은 없으므로 삭제 후 원하는 순서로 다시 등록.

**선택한 스타일 삭제**는 프로그램의 등록 항목만 제거함. 폰의 사진이나 Photo Assist 스타일을 삭제하지 않음.

### 6-5. 생성 버튼 등록

1. 폰에서 스타일 하나를 선택. 아직 생성을 누르지 않음.
2. PC에서 **현재 폰 화면의 버튼 읽기**를 클릭.
3. 목록에서 **생성 [content-desc]**를 선택하고 **생성 버튼 지정**을 클릭. text 항목도 실제 생성 버튼을 가리키면 사용할 수 있으며 둘 다 등록할 필요는 없음.
4. 설정 요약에 생성 버튼이 등록됐는지 확인.

기존 사용자는 기존 버튼과 스타일 설정이 유지. 생성 버튼만 추가 등록하면 됨. 생성 설정이 없으면 자동화는 폰을 조작하기 전에 중단.

### 6-6. 다른 파일로 저장 등록

1. 폰에서 테스트 사진에 스타일 하나를 선택하고 **생성** 버튼을 누른 뒤 생성이 끝날 때까지 대기.
2. **다른 파일로 저장** 버튼이 보이면 PC에서 화면의 버튼을 읽기.
3. 그 버튼 항목을 선택하고 **다른 파일로 저장 지정**을 클릭.
4. 덮어쓰기 버튼을 지정하지 않았는지 확인.
5. 수동 시험을 마무리하고 원본으로 복귀. 수동으로 저장한 결과는 이후 원본 선택에서 제외함.

자동화는 스타일 선택 → 생성 버튼 클릭 → 저장 버튼 대기 → 다른 파일로 저장 순서임. 추가 저장 확인 팝업은 별도 구현이 필요. 엉뚱한 버튼을 대신 지정하지 않음.

설정 변경으로 이전 작업과 다르다는 안내가 나오면 폰의 마지막 결과를 확인한 뒤 **새 작업**을 클릭. 이미 저장한 조합을 다시 실행하면 결과가 중복될 수 있음.

등록 내용은 자동 저장. 별도의 설정 저장 버튼은 없음.

## 7. 결과 수집 메뉴: 폰의 원본 선택

1. **사진 목록 불러오기**를 클릭.
2. 아래 선택 상자에서 대상 폰 폴더를 선택. 폴더는 저장 경로로 표시.
3. 사진 목록에서 원본을 선택.
   - 한 장: 클릭
   - 여러 장 개별 선택: Ctrl을 누르며 클릭
   - 연속 선택: 첫 사진 클릭 후 Shift를 누르며 마지막 사진 클릭
4. **등록된 스타일 N개**를 확인.

현재 정렬은 파일 경로 기준 문자 순서임. 갤러리 날짜순이나 숫자를 자연스럽게 정렬하는 순서와 같다고 보장하지 않음. 선택한 시간 순서가 아니라 PC 목록 표시 순서로 처리.

선택한 폴더 안의 파일만 표시하며 하위 폴더를 합치지 않음. 클라우드에만 있는 사진은 조회·열기가 가능하다고 보장하지 않음.

**기존 결과 사진을 원본과 자동 구분하지 않음. 실행 전 원본만 선택.** 실행을 시작할 때 선택 목록을 고정하므로 그 실행 중 새로 생긴 결과가 자동으로 작업 대상에 추가되지는 않음.

## 8. 사진 한 장 · 스타일 하나 시험

1. 테스트용 원본 한 장을 선택.
2. **첫 사진 · 첫 스타일 시험**을 클릭.
3. 폰에서 원본 → 포토어시스트 → 스타일 → 생성 → 저장 과정을 지켜봅니다.
4. PC 로그의 **같은 폴더 저장 확인**, **완료**를 확인.
5. 폰에서 원본이 유지됐는지, 의도한 스타일인지, 새 사진이 같은 폴더에 저장됐는지 직접 확인.

이 버튼은 실제로 생성·저장. 미리보기 모드가 아님. 여러 사진을 선택했어도 목록상 첫 원본과 첫 등록 스타일만 처리.

폰은 잠금 해제 상태로 두고 실행 중 다른 앱 조작, 촬영, 사진 다운로드 등 새 이미지를 만드는 작업을 병행하지 않음.

## 9. 전체 실행

첫 시험이 성공한 다음 진행.

1. 필요한 나머지 스타일을 등록.
2. **결과 수집** 메뉴의 **새 작업**을 클릭.
3. 처리할 폴더와 원본 사진들을 선택.
4. **전체 수집 시작**을 클릭.

예: 원본 2장, 등록 스타일 3개이면 총 6개 조합을 처리. 첫 원본의 3개 스타일을 완료한 후 다음 원본으로 갑니다.

시험에서 전체 실행으로 선택이 달라지면 새 작업이 필요. 새 작업은 완료 이력을 새로 시작하므로 시험했던 조합도 다시 선택하면 중복 생성. 현재 GUI에는 조합별 제외 기능이 없음.

갤러리가 다른 폴더에 결과를 저장하면 프로그램은 오류로 중단. 결과를 원본 폴더로 자동 이동시키지는 않음.

## 10. 중지·새 작업·다시 실행

| 버튼/상태 | 의미 |
|---|---|
| 중지 | 다음 조작을 중단하도록 요청. 진행 중 통신 때문에 즉시 반응하지 않을 수 있음. |
| 이미 시작한 AI 생성 | 중지 버튼으로 취소되지 않으며 폰에서 계속될 수 있음. |
| 작업 중 창 닫기 | 먼저 중지를 요청. 작업이 멈춘 후 다시 닫기. |
| 새 작업 | progress.json을 보관하고 새 실행 이력을 준비함. 버튼 설정과 폰 사진은 유지. |
| 같은 조건으로 재실행 | 불명확한 작업이 없고 기록·파일 상태가 맞으면 완료 조합을 건너뜁니다. |
| 완료 여부 불명확 | 자동 재시도하지 않음. 폰의 마지막 결과를 직접 확인해야 함. |

오류나 중지 후에는 폰에서 마지막 생성·저장 상태를 먼저 확인. 결과를 확인하지 않고 새 작업을 반복하면 중복 생성 가능. 원본·스타일·기기·설정이 바뀌면 이전 기록과 조건이 달라져 새 작업 안내가 나올 수 있음.

## 11. 기록과 설정

**기록 폴더**를 누르면 PC의 다음 폴더를 열기.

```text
%LOCALAPPDATA%\PhotoAssistCollector
```

| 파일 | 내용 |
|---|---|
| buttons.json | 지정한 버튼과 스타일 목록 |
| progress.json | 현재 작업 조건, 완료 결과, 진행 중 항목 |
| progress_숫자.json | 새 작업 시작 시 보관한 이전 진행 기록 |
| errors.log | 오류 상세 내용 |
| app.lock | Windows에서 두 프로그램이 동시에 실행되는 것을 막는 용도 |

결과 사진은 이 PC 폴더가 아닌 폰에 유지. PC 기록에는 사진 경로와 기기 식별 정보 등이 포함될 수 있으므로 외부에 공유할 때 내용을 확인.

## 12. 자주 발생하는 문제

| 증상/문구 | 확인할 것 |
|---|---|
| requirements.txt를 찾지 못함 | 터미널에서 pwd, dir 실행. desktop 안으로 이동함. |
| python 명령을 찾지 못함 | Python 설치 및 VS Code 터미널에서 인식되는지 확인. |
| No module named ... | 실행에 쓰는 python으로 python -m pip install -r requirements.txt를 완료했는지 확인. |
| 이미 실행 중 | 기존 프로그램 창을 사용하거나 정상 종료한 뒤 다시 실행. |
| 연결된 기기가 없음 | 케이블, 폰 잠금, USB 디버깅, PC 허용, 드라이버를 확인. |
| unauthorized | 폰 잠금을 풀고 USB 디버깅 연결 허용 창을 확인한 뒤 기기 찾기를 다시 클릭. |
| 사진 목록 조회 실패/권한 오류 | 오류 전문을 확인. 폰의 MediaStore 접근 권한·펌웨어에 따른 조정이 필요할 수 있음. |
| 폴더가 안 보임 | 해당 폴더에 폰 로컬 사진이 있는지 확인하고 사진 목록을 다시 불러오기. |
| 원하는 버튼이 목록에 없음 | 폰에서 정확한 화면을 연 뒤 다시 읽기. 비활성·이름 없는 요소 등은 표시되지 않을 수 있음. |
| 버튼을 찾지 못함 | 실제 화면, 등록 항목, 언어, 스와이프 횟수, 추가 팝업 여부를 확인. |
| 같은 이름의 버튼이 여러 개 | 현재 선택 정보로 구분이 불가능함. 다른 고유 속성이나 코드 조정이 필요. |
| 편집 전부터 저장 버튼이 보임 | 원본 진입 상태와 저장 버튼 매핑을 확인. |
| 이전 작업과 선택이 다름 | 마지막 결과 확인 후 새 작업을 사용. |
| 이전 작업 완료 여부 불명확 | 폰에서 결과를 확인하고 중복을 고려해 새 작업을 계획함. |
| 원본 정보 변경 | 원본 상태 확인 후 사진 목록을 다시 불러오기. |
| 새 사진이 동시에 여러 장 생김 | 다른 촬영·다운로드·동기화 여부와 저장 결과를 확인. |
| 다른 폴더에 저장됨 | 실제 저장 위치와 저장 동작을 확인. 자동 이동은 하지 않음. |
| 저장 파일 확인 실패 | 생성/저장 오류·추가 팝업·실제 파일 생성 여부를 확인. |

원본 사진을 열 때마다 화면이 안정되도록 2초 대기. 대기 중에도 중지 가능. 시간을 바꾸려면 automation.py에서 phone.open_original(original) 바로 아래 stop.wait(2)의 숫자를 수정.

일반 버튼 탐색은 최대 약 20초, 생성 버튼 클릭 후 저장 버튼 탐색은 최대 약 180초, 저장 클릭 후 파일 확인은 최대 약 45초임. 통신 시간에 따라 실제 경과시간은 더 길 수 있음. 설정 UI에서 이 대기시간을 바꾸는 기능은 없음.

## 13. 회사 PC로 코드 복사하기

현재 버전은 단일 파일이 아님. 실행용 핵심 Python 파일은 두 개임.

1. 회사에서 허용한 절차로 같은 폴더에 아래 파일을 생성.
   - app.py
   - automation.py
   - requirements.txt
2. 각 파일 내용을 UTF-8로 그대로 복사함. Python 파일의 들여쓰기를 유지.
3. Python과 requirements의 패키지·ADB, USB 연결 환경을 준비함.
4. 해당 폴더에서 python app.py를 실행.
5. 회사 PC에서 기기 찾기와 버튼 설정을 확인.

GitHub pull/push는 실행에 필요하지 않음. 패키지 설치나 USB 디버깅 사용 허용 여부는 별도임. 설치가 제한된다면 회사에서 승인한 배포 경로로 의존성을 준비해야 하며 코드 복사만으로 해결되지 않음.

버튼 설정은 소스코드가 아니라 PC의 buttons.json에 저장. 새 PC에서 다시 등록하거나 승인된 방식으로 설정을 옮긴 뒤 실제 폰에서 재확인. progress.json을 다른 기기 작업에 그대로 재사용하지 않음.

## 14. 유지보수와 현재 범위

- 화면을 바꾸려면 app.py, 자동화 동작을 바꾸려면 automation.py를 수정.
- 현재는 두 파일 구조이며 한 파일 간소화는 아직 미적용.
- 폰 단독 설치용 APK가 아님. 실행하는 동안 PC와 폰 연결이 필요.
- 갤러리/Photo Assist 업데이트, 언어 변경, 다른 기기 사용 후에는 버튼 등록과 한 장 시험을 다시 확인.
- 원본 보존 확인은 경로·크기·수정시간 기반이며 파일 내용 해시 비교가 아님.
- 스타일 품질 판정은 사람이 함. 저장 성공이 스타일 품질 통과를 뜻하지 않음.
- 세로 스타일 목록, 스타일별 다른 분류 경로, 추가 생성 확인·저장 확인 팝업는 추가 구현이 필요.


### 화면이 계속 쌓이던 문제 수정

원본 열기 명령에 `--activity-clear-top`을 추가. Android에 기존 사진 Activity 위의 편집 화면을 정리하도록 요청. 원본 사진 ID는 매번 명시하므로 같은 사진의 다음 스타일과 다음 원본 모두 이 방식을 사용. 사진 삭제, 앱 데이터 초기화, 갤러리 강제 종료 명령은 사용하지 않음.

이전 조합의 새 파일 저장을 확인한 뒤에만 다음 조합을 시작. 오류나 중지로 저장 여부가 불명확하면 화면을 그대로 두고 중단. 정상 완료 후에도 마지막 결과 화면은 남을 수 있으며 갤러리 목록으로 자동 복귀하는 기능은 아님.

이 변경의 S26+ 실기기 효과는 아직 미확인. 갤러리 내부 화면이 Activity가 아닌 다른 방식으로 관리되면 추가 조정이 필요할 수 있음. 원본 2장·스타일 2개로 실행하여 각 결과가 올바른 원본에서 만들어졌는지, 원본이 보존됐는지, 뒤로가기 횟수가 반복 횟수만큼 늘지 않는지 확인. 이전 버전에서 이미 쌓인 화면은 시험 전에 직접 갤러리 목록까지 돌아가 정리함.

참고: [Android 공식 문서의 CLEAR_TOP 설명](https://developer.android.com/guide/components/activities/tasks-and-back-stack#IntentFlags)
