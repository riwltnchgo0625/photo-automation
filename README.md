# Photo Assist 결과 수집기

갤럭시 폰에 있는 사진에 Photo Assist 스타일을 하나씩 적용하고 결과를 모으는 **Windows용 자동화 도구**입니다. 결과 이미지의 품질은 사람이 평가합니다.

Python의 `uiautomator2`로 폰을 조작합니다. Appium·Node.js·Docker는 필요하지 않습니다. 폰 단독 앱이 아니므로 실행 중에는 PC와 USB 연결을 유지해야 합니다.

## 현재 확인한 범위

- 사용자 S26+에서 원본 열기 후 2초 대기를 넣어 한 장·3d 툰 실행에 성공했다는 보고가 있습니다.
- 현재 코드에는 2초 대기와 화면 누적 방지용 원본 열기 옵션이 포함돼 있습니다.
- **화면 누적 수정 효과와 여러 원본·스타일 연속 실행은 실기기 확인이 남아 있습니다.** 코드 테스트 통과가 실기기 성공을 보장하지는 않습니다.

## 1. 실행 준비

- Photo Assist를 사용할 수 있는 갤럭시와 데이터 전송 가능한 USB 케이블
- Windows PC, Python 및 아래 패키지 설치 환경. EXE 빌드 기준은 Windows x64 / Python 3.12입니다.
- 폰의 USB 디버깅 활성화 및 해당 PC 연결 허용
- Photo Assist 생성에 필요한 폰의 인터넷 연결과 계정 설정

PC에 따라 삼성 USB 드라이버가 필요할 수 있습니다. 처음 연결할 때 자동화용 보조 프로그램이 폰에 배치·실행될 수 있습니다.

## 2. ZIP을 받아 VS Code에서 실행

Git 설치 없이 사용할 수 있습니다.

1. GitHub의 **Code → Download ZIP**으로 내려받아 압축을 풉니다.
2. VS Code의 **파일 → 폴더 열기**에서 압축 푼 폴더 안의 **desktop**을 엽니다.
3. **터미널 → 새 터미널**에서 다음 명령을 실행합니다.

```powershell
python -m pip install -r requirements.txt
python app.py
```

이미 `desktop`을 열었으므로 `cd desktop`을 다시 입력하지 않습니다. `requirements.txt`를 찾지 못하면 현재 연 폴더에 `app.py`, `automation.py`, `requirements.txt`가 있는지 확인합니다.

가상환경은 필수가 아닙니다. 위 명령은 현재 선택된 Python 환경에 패키지를 설치합니다.

## 3. 버튼과 스타일 등록 — 처음 한 번

폰을 연결하고 **기기 찾기**에서 대상 기기를 선택합니다. **처음 한 번 · 버튼 설정** 탭에서 폰의 화면을 읽어 버튼을 등록합니다. 화면을 읽고 지정하는 작업 자체는 폰의 버튼을 누르지 않습니다.

| 등록 항목 | 폰에서 직접 열어둘 화면 | PC에서 할 일 |
|---|---|---|
| 포토 어시스트 | 원본 사진 화면 | 화면 읽기 → 해당 항목 선택 → 포토 어시스트 지정 |
| 스타일 탭 | 포토 어시스트 화면 | 화면 읽기 → 스타일 항목 선택 → 스타일 탭 지정 |
| 개별 스타일 | 스타일 목록 | 화면 읽기 → 스타일 항목 선택 → 이름·스와이프 횟수 입력 → 선택한 버튼을 스타일로 추가 |
| 생성 | 스타일 하나를 선택한 화면 | 화면 읽기 → 생성 항목 선택 → 생성 버튼 지정 |
| 다른 파일로 저장 | 폰에서 직접 생성한 결과 화면 | 화면 읽기 → 다른 파일로 저장 항목 선택 → 다른 파일로 저장 지정 |

`content-desc`는 버튼 설명, `text`는 표시 글자입니다. 실제 화면에서 읽힌 항목을 선택합니다. **원본 덮어쓰기 버튼을 저장 버튼으로 등록하지 않습니다.** 목록 펼치기는 해당 화면에서 필요한 경우에만 지정합니다.

### 가로로 넘겨야 보이는 스타일

스와이프 횟수는 **처음 스타일 목록에서 왼쪽으로 넘긴 횟수**입니다. 스타일마다 무조건 1씩 늘리지 않습니다.

- 처음부터 보이면 `0`
- 한 번 넘겨 보이면 `1` — 함께 보이는 여러 스타일에 같은 횟수를 사용 가능
- 두 번 넘겨 보이면 `2`

자동 스와이프는 등록한 스타일 높이에서 화면 너비의 85% 지점부터 20% 지점까지 0.5초 동안 이동합니다. 손으로 넘긴 거리와 다를 수 있으므로 숨겨진 스타일 하나를 먼저 시험합니다. 목록이 매번 처음 위치로 열리는지도 확인합니다.

## 4. 사진 선택과 실행

1. 수동 등록을 마친 뒤 폰에서 원본 사진 화면으로 돌아갑니다.
2. PC의 **실행 → 사진 목록 불러오기**에서 대상 폴더를 선택합니다.
3. **원본만 선택**합니다. 여러 장은 Ctrl 또는 Shift로 선택합니다. 기존 결과 사진을 자동으로 구분하지는 않습니다.
4. 먼저 **선택한 첫 사진 · 첫 스타일만 실행**으로 시험합니다. 이 버튼도 실제 생성·저장을 합니다.
5. 결과와 원본을 확인한 뒤 **새 작업**을 누르고, 원하는 원본들을 선택하여 **선택한 원본 × 모든 등록 스타일 실행**을 누릅니다.

시험한 조합을 전체 실행에도 포함하면 결과가 한 번 더 만들어집니다.

처리 순서는 **사진 목록의 파일 경로 문자순 → 스타일 등록순**입니다. 예를 들어 원본 2장과 스타일 3개를 선택하면 첫 원본의 스타일 3개를 마친 뒤 두 번째 원본을 처리합니다.

각 조합의 동작:

**원본 ID로 열기 → 2초 대기 → 포토 어시스트 → 스타일 탭 → 필요 시 목록 펼치기·가로 이동 → 스타일 선택 → 생성 → 다른 파일로 저장 → 새 파일 확인**

결과는 갤러리 UI가 저장합니다. 프로그램은 **원본과 같은 폴더에 새 파일이 생겼는지 확인**하며, 다른 폴더에 저장되면 중단합니다. 파일을 원본 폴더로 옮기지는 않습니다.

실행 중에는 폰 잠금을 풀어두고 다른 화면 조작·촬영·이미지 다운로드를 하지 않습니다.

## 5. 중지·다시 실행·설정 보관

| 기능 | 동작 |
|---|---|
| 중지 | 이후 조작을 멈춥니다. 이미 시작된 AI 생성을 취소하지는 않습니다. |
| 다시 실행 | 조건이 같으면 저장 완료 기록이 있는 조합은 건너뜁니다. 완료 여부가 불명확하면 멈춥니다. |
| 새 작업 | 이전 진행 이력을 보관하고 새로 시작합니다. 버튼 설정과 폰 사진은 삭제하지 않습니다. |
| 기록 폴더 열기 | PC의 설정·진행·오류 파일 폴더를 엽니다. |

설정과 기록 위치:

```text
%LOCALAPPDATA%\PhotoAssistCollector
```

- `buttons.json`: 버튼·스타일·스와이프 설정. 등록 시 자동 저장됩니다.
- `progress.json`: 작업 조건과 완료·진행 중 조합
- `errors.log`: 오류 상세

**코드를 교체하거나 ZIP을 다시 받아도 같은 PC의 설정은 유지됩니다.** 폰·언어·갤러리 화면 구성이 바뀌면 설정을 재확인합니다. 다른 PC로 옮길 때는 버튼 설정을 다시 등록하거나 `buttons.json`을 옮긴 뒤 한 장 시험을 합니다.

오류 후에는 폰의 마지막 생성·저장 상태를 확인합니다. 확인 없이 새 작업을 반복하면 중복 결과가 생길 수 있습니다.

## 6. 수정할 파일

| 파일 | 역할 |
|---|---|
| `desktop/app.py` | PC 창, 버튼 등록, 원본 선택 |
| `desktop/automation.py` | 폰 연결, 클릭·스와이프, 반복 실행, 저장 확인 |
| `desktop/requirements.txt` | 실행에 필요한 패키지 버전 |
| `desktop/USER_GUIDE.md` | 자세한 사용설명서 |
| `desktop/tests/test_automation.py` | 모의 폰을 이용한 자동 테스트 |
| `desktop/build.ps1` | Windows EXE 제작 |

코드 주석은 변경할 값과 주의할 동작 위주로 짧게 남겼습니다. `automation.py`의 조정 지점은 다음과 같습니다.

| 조정할 값 | 위치 |
|---|---|
| 원본 열기 후 대기 2초 | `execute`의 `stop.wait(2)` |
| 일반 버튼 탐색 최대 20초 | `Phone.click`의 `timeout=20` |
| 생성 후 저장 버튼 탐색 최대 180초 | `execute`의 저장 버튼 클릭 |
| 저장 파일 확인 최대 45초 | `execute`의 `deadline` |
| 가로 이동 거리·속도 | `Phone.swipe_style` |

수정 후 저장하고 프로그램을 닫았다가 `python app.py`로 다시 실행합니다. ZIP으로 받은 PC 파일의 변경은 GitHub에 자동 반영되지 않습니다.

## 7. 현재 제한과 확인할 점

- 화면 누적을 줄이기 위해 원본 열기에 `--activity-clear-top`을 사용합니다. 삼성 갤러리의 실제 화면 구조에 따라 추가 조정이 필요할 수 있습니다. 완료 후 마지막 결과 화면이 남는 것은 가능하며, 갤러리 목록으로 자동 복귀하지 않습니다.
- 최신 코드 시험 전에는 이전에 쌓인 화면을 직접 닫아 갤러리 목록으로 돌아갑니다. **원본 2장·스타일 2개**로 원본 전환, 결과 저장 위치, 뒤로가기 횟수가 계속 늘어나는지 확인합니다.
- 원본 보존은 ID·경로·크기·수정시간 정보로 확인합니다. 사진 내용이나 생성 품질을 판정하지 않습니다.
- 가로 스타일 목록을 지원합니다. 세로 목록, 스타일별 다른 진입 경로, 추가 확인 팝업은 별도 구현이 필요합니다.
- 사진 조회와 원본 열기는 기기 권한·펌웨어에 따라 달라질 수 있습니다. 중복 이름이나 이름 없는 버튼은 등록·클릭이 제한될 수 있습니다.
- 회사 PC의 패키지 설치·USB·실행 제한을 우회하지 않습니다. 회사에서는 허용된 절차로 코드와 의존성을 준비해야 합니다.

## EXE와 테스트

EXE는 GitHub **Actions → Build Windows EXE → 해당 커밋의 성공한 실행 → Artifacts**에서 받을 수 있습니다. 압축을 모두 풀고 `PhotoAssistCollector.exe`와 `_internal` 폴더를 함께 유지합니다. EXE 배포본에는 Python·ADB·필요 패키지가 포함되며, PC에 따라 USB 드라이버는 별도로 필요합니다.

`desktop` 폴더에서 테스트:

```powershell
python -m unittest discover -s tests -v
```

Windows에서 EXE 제작:

```powershell
./build.ps1
```

빌드 결과는 `desktop/dist/PhotoAssistCollector-Windows.zip`입니다. 빌드와 자동 테스트는 실제 폰에서의 생성·저장 검증을 대신하지 않습니다.

더 자세한 절차는 [사용설명서](desktop/USER_GUIDE.md)를 참고하세요. 외부 패키지 라이선스는 EXE 배포 폴더의 `licenses/`에 포함됩니다.
